# Lessons

What changed from the original plan while the work ran, why, and what the next book project should do from the start. Newest last.

1. **Plan review before the first milestone (2026-11-20).** A Fable review of the plan found the estimates at about half of Geber's measured rates (8M against about 17M), facts counted from a first extraction that dropped verse, notes' gaps and italics, no consumer of the readings tried before the costliest milestone, and no answer for a book that marks no process. Next time: estimate from the last book's measured rates, count facts from the XML, and pilot every consumer of the reading format before the readings run.
2. **The paired pages present what the book carries (2026-11-20, the owner).** The plan made the Plain Terms and Plain Language pages depend on a process, so a book without one would have had no primary result. Rewritten (Fable medium, `work/plan_review/review2.md`): the pairs are always present, one per unit the book's own marking sets apart, a process or whatever the book has instead. Next time: define the paired deliverable by what the book carries from the start, never by a process.
3. **Extraction review (M1, 2026-11-20).** The first test compared the text with every space removed, so it could not see the XML file's own indentation, which the code had kept inside words. Two cases: an expanded abbreviation ("per que" for "perque") and gaps beside a line-end break (11 notes). The review agent found them. It also found that a quote check matching part of a word passed, and that apostrophes and "&" were miscounted. The plan's figures from an earlier count (368 paragraphs, 7,487 note words) were corrected to the extraction's. Next time: from the start, treat whitespace next to a line-end break or inside an expansion as layout, test words and spacing (not only signs) against the XML, and make quote matching whole-word.
